### 证明了什么

- GCC 版 `PendSV_Handler` 能完成首次启动和任务间切换。
- SysTick 能在 `OS_Delay` 到期时唤醒任务。
- UART 输出、故障报告、运行脚本的判定链路可用。
- 运行脚本不会把卡死、无输出、主动失败、HardFault、“先 PASS 后故障”判成通过。

### 没有证明什么

- V-001 本身没有检查栈帧内容；后续补充见 V-005。
- 没有覆盖临界区、信号量、互斥锁、队列等内核行为。
- QEMU 的时间不代表真机周期。
- 冒烟用例的 A/B 打印顺序在两次运行中不同（`A0 B0 A1 B1` 与 `A0 B0 B1 A1`），所以只断言偏序；是否符合 FIFO 契约，阶段 2 核对，现在**不能**据此判断内核正确或错误。

| 证据 | `tests/build/logs/SCHED-01-before.log`、`SCHED-01/02/03.log`、`SCHED-repeat.log`、`full-rebuild.log`；日志被忽略，以下摘录保留关键现象 |

修复前，先用原 `OS_Delay` 构建 SCHED-01。该用例关闭 SysTick 后让 A 调用 `OS_Delay(0)`，B 观察 A 的状态与延时队列。实际输出：

```text
CASE SCHED-01
CHECK create_a PASS
CHECK create_b PASS
CHECK yield_keeps_a_ready_and_delay_list_empty FAIL
TEST:FAIL
RESULT: FAIL saw TEST:FAIL (qemu exit=None)
runner_exit=1
```

原因：旧实现不区分 0 与正延时，总会把 A 标为阻塞并放进延时队列；没有下一次 tick 就无法继续。最小修复仅给 `OS_Delay(0)` 增加就绪队列轮转、重选任务的分支，同步头文件和契约；不改正延时路径，不解决尚未验证的 ISR/外层临界区误用。

| 用例 | 期望 | 实际 |
|---|---|---|
| SCHED-01 | tick 不推进，事件 1～7 顺序正确；A/B 主动交替；B 独自就绪时不阻塞，位图正确 | 7 个事件 tick 均为 0，状态/队列/位图检查通过，QEMU 自然退出 0 |
| SCHED-02 | 两个同优先级忙等任务由周期 tick 切换，事件 1～4 按序，切换间 tick 增加 | 事件 tick 为 0、1、2、3；QEMU 自然退出 0 |
| SCHED-03 | 高优先级任务延时，低优先级任务运行并忙等；到期后高优先级抢占 | 事件 tick 为 0、0、3；高任务就绪且延时表清空，QEMU 自然退出 0 |

## V-008：semihosting 结束协议与运行器负例

板级 `test_support.c/.h` 使用 `SYS_EXIT_EXTENDED`（操作号 `0x20`，原因 `0x20026`）返回目标状态。运行器显式启用 native semihosting，要求完整编号行、完整 PASS 行和自然退出 0；目标卡死或运行器主动 kill 不能计为通过。普通检查失败和系统故障报告可以退出 1；原内核断言仍是死循环，运行器根据 `OS ASSERT FAILED` 判失败并终止它。

| 用例 | 行为 | 期望运行器码 | 实际 |
|---|---|---:|---|
| NEG-01 | 无输出卡死 | 2 | 超时，2 |
| NEG-02 | 主动输出失败 | 1 | `saw TEST:FAIL`，1 |
| NEG-03 | HardFault | 1 | 故障报告，1 |
| NEG-04 | PASS 后 HardFault | 1 | `saw TEST:FAULT`，1 |
| NEG-05 | PASS 后继续死循环 | 2 | 不退出，3 秒超时，2 |
| NEG-06 | PASS 后 semihosting 退出 7 | 1 | `qemu exit=7, expected 0`，1 |
| NEG-07 | semihosting 退出 0，但无 PASS | 1 | `missing complete TEST:PASS line`，1 |
| NEG-08 | `List_Init(NULL)` 触发原内核断言 | 1 | `saw OS ASSERT FAILED`，1 |
| NEG-09 | 实际事件 2、1，期望 1、2，复用正例比较器 | 1 | 两项 `event_order FAIL`，1 |
| NEG-10 | 输出错误编号，但有 PASS 和退出 0 | 1 | `missing CASE NEG-10`，1 |

汇总入口实际打印 20 行顶层 PASS：4 个 QEMU 正例、10 个 QEMU 负例、GDB 正例与 4 个 GDB 负例、1 个主机套件。`failures: 0`，退出码 0；GDB 仍为 37 项，主机仍为 27 项及 2 个负例。GDBNEG-02 改用 `neg_hang.elf` 保证不可达断点的目标持续运行，防止新冒烟程序正常退出干扰超时检查。
