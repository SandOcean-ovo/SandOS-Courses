## V-001：QEMU 双任务冒烟与运行脚本负例

| 项 | 内容 |
|---|---|
| 日期 | 2026-10-31 首次运行；2026-11-01 加注释重构后重新运行 |
| 命令 | `bash tests/scripts/run_all.sh` |
| 结果 | 两次运行均为 5 项符合预期，`failures: 0`，退出码 0 |

| 用例 | 程序 | 脚本应给出 | 实际 |
|---|---|---|---|
| SMOKE-01 | `ports/qemu-mps2/main.c` | 通过；`A0`、`B0`、`A2` 按序出现，有 `TEST:PASS` | 通过 |
| NEG-01 | `neg_hang.c` | 超时，退出码 2 | 退出码 2，输出 0 字节 |
| NEG-02 | `neg_fail.c` | 失败，退出码 1 | 退出码 1，`saw TEST:FAIL` |
| NEG-03 | `neg_fault.c` | 失败，退出码 1 | 退出码 1，输出 `FAULT: HardFault PC=000001F4 …` 与 `TEST:FAULT` |
| NEG-04 | `neg_pass_text_only.c` | 失败，退出码 1 | 退出码 1，`saw TEST:FAULT after TEST:PASS` |

### 证明了什么

- GCC 版 `PendSV_Handler` 能完成首次启动和任务间切换。
- SysTick 能在 `OS_Delay` 到期时唤醒任务。
- UART 输出、故障报告、运行脚本的判定链路可用。
- 运行脚本不会把卡死、无输出、主动失败、HardFault、“先 PASS 后故障”判成通过。

### 没有证明什么

- 没有检查栈帧内容（GDB 验证尚未做）。
- 没有覆盖临界区、信号量、互斥锁、队列等内核行为。
- QEMU 的时间不代表真机周期。
- 冒烟用例的 A/B 打印顺序在两次运行中不同（`A0 B0 A1 B1` 与 `A0 B0 B1 A1`），所以只断言偏序；是否符合 FIFO 契约，阶段 2 核对，现在**不能**据此判断内核正确或错误。

## V-002：脚本自检——故意改错期望码

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-01 |
| 操作 | 把 `run_all.sh` 中 NEG-02 的期望退出码从 `1` 临时改成 `0`，运行后恢复 |
| 命令 | `bash tests/scripts/run_all.sh` |
| 预期 | 报 `FAIL  NEG-02 (runner exit 1, expected 0)`，`failures: 1`，退出码 1 |
| 实际 | 与预期一致；恢复后重新运行 5 项全过，`git diff` 确认脚本已恢复 |
| 意义 | 说明 `run_all.sh` 在预期不符时确实会失败，而不是总是返回 0 |

## V-004：两项排错结论的对照验证

对应《排错记录》第 1 条和第 6 条，2026-11-01 重新验证，结果已写进该文档：

- 第 1 条：用删掉 `.init/.fini` 的链接脚本重新链接，`_init` 只有 `push`/`nop`，缺少返回指令；现行脚本的 `_init` 完整。**没有**进一步确认链接器内部为什么这样放置，未作断言。
