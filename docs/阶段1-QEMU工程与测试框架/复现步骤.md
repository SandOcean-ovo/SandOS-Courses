# 阶段 1：复现步骤

> 目标：从阶段 0 完成后的 `dev` 分支出发，得到一个能在 QEMU 上跑起来并自动判定结果的工程。
> 命令均在 Git Bash 中、仓库根目录执行。Linux/macOS 把 `mingw32-make` 换成 `make`。
> 如果只想验证现成的结果，直接做“步骤 7”；要从头搭建，按顺序做步骤 1~7。

## 步骤 1：确认前置条件

```bash
git rev-parse upstream-baseline-25a06bd     # 预期 25a06bdea89a467ec7e85fe7f766705b58837961
qemu-system-arm -M help | grep mps2-an385   # 预期出现 mps2-an385 这一行
arm-none-eabi-gcc --version | head -1
mingw32-make --version | head -1
```

**失败时**：没有 `mps2-an385` 说明 QEMU 太旧或没装；`make` 找不到时 Windows 下确认 `C:/msys64/mingw64/bin` 在 PATH 中。

## 步骤 2：放入 CMSIS Core 头文件

```bash
S="C:/Keil_v5/ARM/PACK/ARM/CMSIS/6.1.0"
mkdir -p third_party/cmsis/m-profile
for f in core_cm3.h cmsis_version.h cmsis_compiler.h cmsis_gcc.h cmsis_clang.h cmsis_armclang.h; do
  cp "$S/CMSIS/Core/Include/$f" third_party/cmsis/
done
cp "$S"/CMSIS/Core/Include/m-profile/*.h third_party/cmsis/m-profile/
cp "$S/LICENSE" third_party/cmsis/LICENSE
```

**预期**：`third_party/cmsis/core_cm3.h` 存在。没有 Keil 时，从 <https://github.com/ARM-software/CMSIS_6> 的 `v6.1.0` 标签取 `CMSIS/Core/Include/` 同名文件，效果相同。
然后写 `third_party/cmsis/来源说明.md`，记录来源路径、版本 6.1.0 与许可 Apache-2.0。

## 步骤 3：改移植层（2 处）

1. `rtos/Portable/ARM_CM3/os_cpu.h`：把 `#include "stm32f1xx.h"` 换成 `#include "os_board.h"`。
2. `rtos/Portable/ARM_CM3/os_cpu.c`：把 `uint32_t ticks = 72000000 * ms / 1000;` 换成 `uint32_t ticks = (OS_CPU_CLOCK_HZ / 1000U) * ms;`。

**检查**：`git diff rtos/Portable/ARM_CM3/os_cpu.c` 只应出现这一处实质修改（外加注释）。

## 步骤 4：新增板级与移植文件

按《代码说明.md》逐个创建（内容以仓库里的文件为准）：

- `rtos/Portable/ARM_CM3/os_cpu_a_gcc.S`
- `ports/qemu-mps2/` 下的 `os_board.h`、`startup.c`、`link.ld`、`uart.c`、`uart.h`、`syscalls.c`、`main.c`、`Makefile`

## 步骤 5：构建

```bash
mingw32-make -C ports/qemu-mps2
```

**预期**：末尾打印一行 `size` 统计（`text/data/bss`），生成 `ports/qemu-mps2/build/main.elf`。
会看到一条来自上游的警告 `os_core.c: unused parameter 'param'`，属正常，不影响结果。
**失败时**：对照《排错记录》。常见的是链接阶段 `undefined reference to 'end'`（链接脚本缺 `PROVIDE(end = _ebss)`）。

## 步骤 6：手动运行一次

```bash
qemu-system-arm -M mps2-an385 -cpu cortex-m3 -nographic -monitor none \
  -serial stdio -kernel ports/qemu-mps2/build/main.elf
```

**预期**输出（A、B 两行的先后在不同运行中可能互换）：

```
SandOS qemu-mps2 boot
A0
B0
A1
B1
A2
B2
TEST:PASS
```

程序不会自己退出，按 `Ctrl+A` 然后 `X` 结束 QEMU。
**如果没有任何输出**：不要等，直接去《排错记录》第 1 条。

## 步骤 7：运行全部自动用例

```bash
bash tests/scripts/run_all.sh
```

**预期**（顺序固定）：

```
PASS  SMOKE-01
PASS  NEG-01 (runner exit 2 as expected)
PASS  NEG-02 (runner exit 1 as expected)
PASS  NEG-03 (runner exit 1 as expected)
PASS  NEG-04 (runner exit 1 as expected)
failures: 0
```

脚本退出码为 0。`PASS` 是指“结果符合预期”，其中 4 个 `NEG` 本身是**故意失败**的程序，脚本必须判它们失败才算对。

## 步骤 8：自检脚本是否可信

故意破坏一次，确认脚本会报错，而不是照样通过。例如把 `tests/scripts/run_all.sh` 里 `NEG-02` 的期望码从 `1` 改成 `0`，重新运行：

```bash
bash tests/scripts/run_all.sh; echo "exit=$?"
```

**预期**：出现 `FAIL  NEG-02 (runner exit 1, expected 0)`，`failures: 1`，`exit=1`。验证完立刻改回去。
