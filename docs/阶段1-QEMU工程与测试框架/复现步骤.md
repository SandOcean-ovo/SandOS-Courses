## 步骤 10：单独复现 GDB 与主机测试（本轮新增）

本节命令在仓库根目录运行。汇总入口会自动做同样的检查。

```bash
mingw32-make -C ports/qemu-mps2
python tests/scripts/run_gdb.py ports/qemu-mps2/build/main.elf tests/gdb/pendsv_frame.gdb --timeout 15
```

预期 37 条 `GDBCHK ... PASS`，最后 `GDBRESULT PASS`、`RESULT: PASS (37 checks)`，退出码 0。脚本自动连接本地空闲端口；`.gdb` 文件中不再写 `target remote`。它使用普通 GDB 命令，不依赖 GDB 内嵌 Python。

要手动观察，在一个终端启动：

```bash
qemu-system-arm -M mps2-an385 -cpu cortex-m3 -nographic -monitor none \
  -serial null -semihosting-config enable=on,target=native -S -gdb tcp:127.0.0.1:1234 -kernel ports/qemu-mps2/build/main.elf
```

另一个终端运行 `arm-none-eabi-gdb ports/qemu-mps2/build/main.elf`，再输入：

```gdb
target remote 127.0.0.1:1234
break PendSV_Exit
continue
x/8wx $psp
x/16wx CurrentTCB->stackPtr
```

- `PendSV_Exit` 在 `bx lr` 之前：R4–R11 已恢复，PSP 指向新任务的 8 字硬件帧。此时 `x/16wx $psp` 会读过该帧，不能把后 8 字解释为软件保存寄存器。
- 在这个位置看完整 16 字上下文应使用 `CurrentTCB->stackPtr`：前 8 字是 R4–R11，后 8 字是 R0/R1/R2/R3/R12/LR/PC/xPSR。
- `PendSV_Saved` 在旧任务 `stackPtr` 已更新、尚未读取 NextTCB 的位置；PSP 仍指向旧任务硬件帧。使用 `x/16wx CurrentTCB->stackPtr` 查看刚保存的完整上下文。
- 刚进入 PendSV 时，CPU 当前 PC/LR 属于处理程序；被打断任务的 PC/LR 在硬件帧中。首次启动从 MSP 进入，此时旧 PSP 不能当作有效任务帧。

主机测试：

```bash
# Windows 本机；Linux 使用自己的主机 gcc，无需此 PATH 行
export PATH=/c/msys64/ucrt64/bin:$PATH
python tests/scripts/run_host.py
# 也可分别构建/运行（此直接入口没有 Python 运行器的超时保护）
mingw32-make -C tests/host test neg
```

预期正例 `HOSTSUMMARY total=27 failed=0`。负例会有意打印 `FAIL`，运行器确认退出码恰好为 1 后报告 `PASS HOSTNEG-01/02`；不是隐藏失败。所有 `.exe` 和日志在忽略的 `build/` 内。

GDB 负例的期望退出码依次为 1、2、1、1。除 `neg_never_hit.gdb` 外，可直接用 `tests/gdb/negative/` 对应脚本替换单项命令参数。不可达断点负例须先构建 `APP=../../tests/target/negative/neg_hang.c`，再用 `neg_hang.elf` 配 `neg_never_hit.gdb`，确保目标持续运行到超时。

## 步骤 11：调度事件与退出协议

```bash
mingw32-make -C ports/qemu-mps2 APP=../../tests/target/task_yield.c
python tests/scripts/run_qemu.py ports/qemu-mps2/build/task_yield.elf --case SCHED-01
```

预期 `EVENT 1`～`EVENT 7` 全部按序出现，tick 值相同，最后 `TEST:PASS`、`RESULT: PASS qemu exit=0`。事件与状态由目标程序实际比较，运行器还检查编号和退出码。

将应用改为 `tick_preempt.c` / `delay_wake.c`、对应 ELF 名及编号改为 SCHED-02 / SCHED-03，可分别观察周期 tick 轮转和延时到期抢占。不要用这些 tick 数换算真机周期性能。

新增退出负例已纳入汇总入口。要单独验证：构建 `APP=../../tests/target/negative/neg_exit_status.c`，运行 `neg_exit_status.elf --case NEG-06`，预期即使有 PASS，运行器仍报告 `qemu exit=7, expected 0` 并退出 1。
