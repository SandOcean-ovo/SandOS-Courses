## 1. 本阶段目标

先建立一个可观察、可自动判定的最小环境：能在 QEMU 的 `mps2-an385`（Cortex-M3）上启动内核、切换任务，并且测试脚本能分辨“通过”“失败”“卡死”“崩溃”。内核缺陷的修复放到阶段 2，所以**本阶段没有修改 `os_core.c`**。

## 3. 本阶段改动清单

### 3.1 修改了上游文件（仅 2 个，且是最小改动）

| 文件 | 改动 | 原因 |
|---|---|---|
| `rtos/Portable/ARM_CM3/os_cpu.h` | `#include "stm32f1xx.h"` 改为 `#include "os_board.h"` | 让通用内核不依赖某个厂商头文件，板级头文件由各 `ports/<板>/` 提供 |
| `rtos/Portable/ARM_CM3/os_cpu.c` | `72000000 * ms / 1000` 改为 `(OS_CPU_CLOCK_HZ / 1000U) * ms` | 去掉写死的 72 MHz；QEMU 为 25 MHz |

`rtos/Src/os_core.c` 一字未改，历史缺陷仍在，留给阶段 2。

## 4. 关键决定与理由

| 决定 | 理由 |
|---|---|
| 内置一份 CMSIS Core 头文件，而不是引用 Keil 安装目录 | GitHub Actions 和读者环境里没有 `C:/Keil_v5`；复制 Core 头文件（只有几个文件）就能让 GCC 路线自洽。来源和许可记录在 `third_party/cmsis/来源说明.md` |
| 板级头文件放在 `ports/qemu-mps2/`，而不是 `rtos/` | 通用内核不应知道具体板子；以后 STM32 工程提供自己的 `os_board.h` 即可 |
| 新建 `os_cpu_a_gcc.S`，不改原 `os_cpu_a.s` | 原文件是 armasm 语法，AC6 的汇编选择要在 Keil 工程里显式配置，不用条件编译混在一起 |
| 运行脚本只断言“偏序”，不断言 A、B 任务的精确交错 | 同优先级任务同一 tick 被唤醒时，打印顺序在两次运行中不同（见《验证记录》）。是否符合 FIFO 契约要等阶段 2 再核对，现在不能把它固定成期望 |
| 负例是必做项 | 如果脚本会把卡死、故障当成通过，所有正例都不可信 |
| `SysTick_Handler` 放进板级 `startup.c` 转发给 `OS_Tick_Handler` | 上游仓库没有定义 `SysTick_Handler`，它原本在用户工程的中断文件里 |

## 5. 已知限制

1. **NVIC 优先级位数**：QEMU 的 `mps2-an385` 为 3 位，STM32F103 为 4 位。`os_cpu.c` 里写的 `NVIC_SetPriority(PendSV, 15)`、`SysTick, 14` 在 3 位下经 CMSIS 左移后会被截断为 7 和 6，“PendSV 比 SysTick 优先级更低”的相对顺序仍成立，但这个数值写法依赖板子，正式教材需要说明。
2. QEMU 的时钟与运行时间**不代表真机周期**，只用于功能与顺序验证。
3. 目前只验证了正常路径与 4 个脚本负例，没有检查栈帧内容和临界区行为。
4. `os_core.c` 编译时有一条 `unused parameter 'param'` 警告（`IdleTask`），属于上游代码，未处理。
