## 3. 实际验证

### ENV-AC5-01：最小编译探针

在 `tests/build/environment-20261108/ac5_probe.c` 写入不依赖库和设备包的函数 `unsigned int ac5_probe(void) { return 0x528U; }`，实际执行：

```powershell
& 'C:/Keil_v5/ARM/ARMCC/bin/armcc.exe' --cpu Cortex-M3 --c99 -c tests/build/environment-20261108/ac5_probe.c -o tests/build/environment-20261108/ac5_probe.o
```

预期：退出 0 且生成目标文件。实际：退出 1，目标文件不存在，首行 `Error: C9555E: Failed to check out a license.LICENSE ERROR (R201(2): INVALID LICENSE ID CODE (LIC))`。日志位于 `tests/build/environment-20261108/ac5-compile.log`，结果在同目录 `ac5-result.txt`。

证明了本轮命令行 AC5 调用被许可检查阻断；不能推定 GUI 中现有工程的调用结果，也不对许可来源作判断。未进行 Keil 启动、SysTick、PendSV 或寄存器／内存仿真，不能写成“Keil 仿真不支持”。后续先在现有 μVision 的 License Management 核对实际授权与调用环境，再重试同一探针；本轮未修改任何许可文件或配置。
