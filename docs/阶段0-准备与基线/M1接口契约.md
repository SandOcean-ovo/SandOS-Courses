# M1 API 契约

状态：草案，2026-10-31。依据 `TODO.md`「已确定的 M1 接口边界」。实现、测试与教材都以本文为准；变更须同步三者。
范围：单核 Cortex-M3、固定优先级、静态分配。数值越小优先级越高（与现有 `os_core.c` 的 `Priority` 比较方向一致，阶段 2 开工时用代码核对）。

## 1. 通用规则

| 项 | 约定 |
|---|---|
| 时间单位 | tick，默认 1 kHz（1 tick = 1 ms）。毫秒到 tick 的转换显式进行 |
| 调用上下文 | 任务上下文：全部 API。ISR：仅 `*FromISR` |
| 阻塞 API 的禁用场景 | 在 ISR 或用户外层临界区中调用：**在修改任何内核状态之前**拒绝：状态接口分别返回 `OS_ERR_ISR`／`OS_ERR_CRITICAL`，MemGet 返回 NULL，Delay 断言。API 内部自己的临界区不受影响 |
| 返回值 | 成功 `OS_OK`；参数错误 `OS_ERR_PARAM`；资源不可用 `OS_ERR_RESOURCE`；其余沿用 `os_core.h` 的 `OS_Status` |
| 配置 | 最大优先级、tick 频率、断言、栈检测、benchmark 集中在 `os_config.h`；benchmark 默认关闭 |

## 2. 临界区

- 采用 PRIMASK：进入时保存当前屏蔽状态并屏蔽中断；退出时恢复到进入前的状态。
- 内核自身支持嵌套；退出到最外层时恢复最外层进入前的状态，**不无条件开中断**。
- 进入前中断已被用户屏蔽时，退出后仍保持屏蔽。

## 3. 任务

- 仅支持调度器启动前静态创建；检查栈大小、栈对齐、优先级范围。参数非法返回 `OS_ERR_PARAM`。
- 不提供公开的挂起、恢复、删除 API。
- 调度器启动：创建空闲任务；启动窗口内 tick 不得触发断言或错误调度。

## 4. 等待与唤醒顺序

| 对象 | 等待顺序 |
|---|---|
| 信号量、队列、内存池 | FIFO |
| 互斥锁 | 按优先级，同优先级 FIFO |

唤醒后若被唤醒任务优先级高于当前任务，立即请求切换。

## 5. 各对象行为

**信号量**（2026-11-01 锁定计数接口）：

- `OS_SemInit(OS_Sem *p_sem, uint16_t init_count)`：仅在线程/初始化上下文、对象未发布且没有等待者时调用。设置 `count=init_count` 并清空等待表；初值单位是可消费次数，范围 0～`UINT16_MAX`。空指针返回 `OS_ERR_PARAM`，成功返回 `OS_OK`。不支持对使用中的对象重新初始化；本轮不新增运行时上下文检测。
- `OS_SemWait` 在线程中调用，正计数消费一次；为 0 时无限等待，无有限超时；ISR/用户外层临界区按下文 2026-11-12 契约在入口拒绝。
- `OS_SemPost` 在线程中调用；有等待者时按 FIFO 直接交接一次许可，计数不增加；无等待者时计数增加一次。计数已为 `UINT16_MAX` 且无等待者时返回新错误码 `OS_ERR_OVERFLOW=4`，计数及队列不变。空指针返回 `OS_ERR_PARAM`。
- `OS_SemPostFromISR` 不阻塞，采用同样的计数上限。空指针或溢出失败时不修改唤醒输出；本轮只验证无等待者边界分支。成功唤醒标记累积、共享状态保护与 ISR 尾部调度仍需完成后续 ISR 专项，不能仅凭本轮结果宣称整个接口已中断安全。
- 不改变其他已有错误码的数值。计数不是时间参数。

**互斥锁**：
- 同一任务可对同一把锁递归加锁，嵌套超限返回 `OS_ERR_NESTING`。
- 单锁优先级继承：持有者优先级提升到最高等待者优先级，最后一次解锁时恢复。
- 同一任务在已持有一把锁的情况下对**另一把**锁加锁：检查并拒绝，返回错误，不改变任何状态。
- 非持有者解锁返回 `OS_ERR_NOT_OWNER`。
- 解锁交接给等待者时，等待者须回到就绪状态并进入对应就绪链表。

**队列**：接收可无限等待；发送遇满立即返回 `OS_ERR_Q_FULL`，不阻塞。有限超时和阻塞发送在阶段 2B 引入。

**延时**：`OS_Delay(0)` 让出执行机会，不进入延时队列。`OS_Delay(n)` 至少延时 n 个 tick 边界（精确语义在阶段 2 用测试固定）。

2026-11-01 细化零延时：保持 `TASK_READY`、保留就绪位图，将当前任务移到本优先级队尾，重新选择下一任务；没有同优先级就绪伙伴时继续运行，不把执行机会交给较低优先级任务。不依赖下一次 tick，不改变正延时者的队列。QEMU 用例 `SCHED-01` 验证该行为；ISR／外层临界区的拒绝按下文 2026-11-12 契约断言。

## 6. ISR 规则

- 只使用 `FromISR` 接口，不阻塞。
- 访问共享状态时保存并恢复屏蔽状态。
- 若唤醒了更高优先级任务，通过输出参数告知，调用方在 ISR 尾部调用 `OS_YieldFromISR`。该接口在阶段 2 实现。

## 7. M1 明确不做

通用阻塞超时、多锁优先级继承与多锁恢复、队列阻塞发送、公开任务挂起／恢复／删除、传递优先级继承、AC6 完整兼容、RISC-V。

### 2026-11-08 互斥锁修复前锁定的细节

沿用实际接口名 `OS_MutexInit` / `OS_MutexPend` / `OS_MutexPost`（此前泛称 Lock/Unlock 仅指行为）。初始化仅对未发布对象使用；Pend/Post 在线程上下文、没有用户外层临界区时调用。当时上下文拒绝尚未实现；2026-11-12 已补 Pend 的入口拒绝，Post 仍须遵守调用边界。

- 单任务最多持有一把不同的互斥锁；同一把递归深度包含首次持有，范围 1～`UINT8_MAX`（255）。深度已为 255 时再次 Pend 返回 `OS_ERR_NESTING`，计数、所有权、队列及优先级不变。
- 已持有一把锁时，对第二把不同锁调用 Pend，无论第二把为空闲还是被占用，均返回已有错误码 `OS_ERR_RESOURCE`，不阻塞、不继承、不取得第二把锁。未持锁者申请被占用的第一把锁仍可无限等待。
- 同优先级等待者保持 FIFO，高优先级先交接。最终 Post 先恢复旧持有者基础优先级，再将锁、深度 1 与持锁记录直接交给等待者；等待者置 READY 后才加入就绪表，清理等待节点一次。释放后无等待者则清空所有权和持锁记录。
- 同锁递归 Post 仅减深度，尚未归零不撤销继承、不唤醒等待者。非持有者 Post 返回 `OS_ERR_NOT_OWNER`，不改变状态。没有时间参数，仍不支持有限超时或传递继承。

验收：MUTEX-01 在无 tick 的 L→H→HH 两次交接中核对状态、优先级、链表、位图和事件顺序；MUTEX-02 通过真实任务覆盖 255/256 边界、递归释放、非持有者、空闲及被占用的第二把锁拒绝。新增状态字段如改变 TCB 布局，仍须保留首字段 stackPtr 的汇编约定，并运行原 GDB 栈帧回归。

### 2026-11-12：阻塞／调度 API 上下文拒绝

本轮不改变函数签名。检查发生在参数有效性检查后、API 自身进入临界区之前，且不以资源是否立即可得决定能否使用阻塞接口。

- `OS_SemWait`、`OS_MutexPend`、`OS_QueueReceive`：Handler 模式优先返回已有 `OS_ERR_ISR=20`；线程中的用户外层临界区或禁止调度的屏蔽状态返回新增 `OS_ERR_CRITICAL=21`。拒绝不改对象、缓冲区、TCB、队列、位图、调度请求与进入前屏蔽状态。
- `OS_MemGet`：保留指针返回，非法参数／上述非法上下文返回 NULL，不能消费空闲块；本轮不引入阶段 2B 的状态输出参数。
- `OS_Delay`：包含 Delay(0) 在内，只能在允许调度的线程上下文调用。非法上下文先触发 OS_ASSERT，且断言前不修改任何内核状态；保留 void 签名，不假装能返回 OS_Status。断言关闭／返回后的防御路径仍直接 return，不执行延时逻辑。
- Cortex-M3 以 IPSR 判断异常上下文；以 PRIMASK、BASEPRI、FAULTMASK 判断调用者屏蔽条件。当前 PendSV 为最低可配置优先级，非零有效 BASEPRI 也会阻止该切换，因此同样拒绝。这里只读寄存器，不修改临界区保存／恢复实现。
- 已经位于 API 内部的临界区，不再次调用此入口检查。合法调用仍允许阻塞、被唤醒后完成，不得误拒绝。
- 空参数仍优先返回原参数错误（MemGet 为 NULL）；非阻塞 task 版 Post／Send、FromISR 完整保护与启动前资源操作的统一约束不是本轮新增承诺。

验收：真实 SVC、两层用户临界区、原始 PRIMASK、BASEPRI、FAULTMASK；资源可用与不可用时均检查拒绝及逐字节快照不变。对 Delay 的断言使用 GDB 在 OS_AssertFailed 入口停止，检查断言前状态；不删除或替换生产断言。
