## 2. 历史问题的静态复核

**方法**：只阅读源码，没有运行。因此下表“静态阅读所见”不等于“已复现”，复现要等阶段 2 先写失败用例。

| 问题 | 位置（基线 `25a06bd`） | 静态阅读所见 |
|---|---|---|
| 信号量计数未初始化 | `os_core.c` 的 `OS_SemInit` | 基线只调用 `List_Init`，没有给 `count` 赋值；当前已由阶段 2 SEM-01 复现并修复 |
| 临界区退出未恢复进入前的屏蔽状态 | `os_core.c` 的 `OS_EnterCritical` / `OS_ExitCritical` | 嵌套计数归零后无条件 `OS_Enable_IRQ()`，没有保存进入前的 PRIMASK |
| 首次启动窗口的 tick | `os_core.c` 的 `OS_StartScheduler` / `OS_Tick_Handler` | `OS_Init_Timer(1)` 先于 `g_OSRunning = TRUE`，启动窗口里 `CurrentTCB` 为 `NULL`，与 `OS_ASSERT(CurrentTCB != NULL)` 的关系需用测试确认 |
| 互斥锁交接 | `os_core.c` 的 `OS_MutexUnlock` | 弹出等待者后直接 `OS_ReadyListAdd`，需确认其 `State` 有没有回到 `TASK_READY` |
| 继承时的就绪表 | `os_core.c` 的 `OS_MutexLock` | 只有 `Owner->State == TASK_READY` 才摘链改优先级，其余只改数值，需构造用例验证 |
| 固定 72 MHz | `ARM_CM3/os_cpu.c` 的 `OS_Init_Timer` | 基线写死 `72000000`。**该项已在阶段 1 改为 `OS_CPU_CLOCK_HZ`**，见阶段 1 文档 |

### 已定接线接口（设计约定，尚未接线验证）

- ST-Link 采用 SWD：SWDIO → PA13，SWCLK → PA14，GND 共地；如探针有 VTref／目标电压检测脚，应接目标 3.3 V 参考，具体脚位依下载器说明；NRST 接板上 NRST 作为后续复位调试选项。
- USART1 使用默认引脚：PA9（TX）→ USB-TTL 的 RX，PA10（RX）→ USB-TTL 的 TX，GND 共地；接口要求 3.3 V TTL 电平，模块型号及串口驱动留待实际硬件确认，不假定 ST-Link 自带串口。
- 板侧工作电压按 3.3 V。板上是否可从 USB／5 V 经稳压输入须核对实际 PCB，未确认前不按通用最小板图假定。目标只选一个明确电源来源，不将 ST-Link 的参考电压脚当成必然供电脚。
- 本轮仿真核心时钟设为 8 MHz，不代表已验证实物 HSE 起振或 PLL 72 MHz。后续真机工程单独初始化和验证时钟。

引脚／器件依据：[ST DS5319 Rev 20，2025-07，第 3 节 Table 5](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf)，2026-11-08 核对。实际 PCB 电源连接与外接配件仍以实物为准。STM32 参考手册在线 PDF 本次读取因体积限制失败，未将未读取部分作为已核实依据。
