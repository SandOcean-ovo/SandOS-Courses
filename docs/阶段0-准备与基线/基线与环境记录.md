## 2. 历史问题的静态复核

**方法**：只阅读源码，没有运行。因此下表“静态阅读所见”不等于“已复现”，复现要等阶段 2 先写失败用例。

| 问题 | 位置（基线 `25a06bd`） | 静态阅读所见 |
|---|---|---|
| 信号量计数未初始化 | `os_core.c` 的 `OS_SemInit` | 只调用 `List_Init`，没有给 `count` 赋值 |
| 临界区退出未恢复进入前的屏蔽状态 | `os_core.c` 的 `OS_EnterCritical` / `OS_ExitCritical` | 嵌套计数归零后无条件 `OS_Enable_IRQ()`，没有保存进入前的 PRIMASK |
| 首次启动窗口的 tick | `os_core.c` 的 `OS_StartScheduler` / `OS_Tick_Handler` | `OS_Init_Timer(1)` 先于 `g_OSRunning = TRUE`，启动窗口里 `CurrentTCB` 为 `NULL`，与 `OS_ASSERT(CurrentTCB != NULL)` 的关系需用测试确认 |
| 互斥锁交接 | `os_core.c` 的 `OS_MutexUnlock` | 弹出等待者后直接 `OS_ReadyListAdd`，需确认其 `State` 有没有回到 `TASK_READY` |
| 继承时的就绪表 | `os_core.c` 的 `OS_MutexLock` | 只有 `Owner->State == TASK_READY` 才摘链改优先级，其余只改数值，需构造用例验证 |
| 固定 72 MHz | `ARM_CM3/os_cpu.c` 的 `OS_Init_Timer` | 基线写死 `72000000`。**该项已在阶段 1 改为 `OS_CPU_CLOCK_HZ`**，见阶段 1 文档 |

## 5. 本机待决问题

1. git 全局代理 `127.0.0.1:7897` 当前不可用，会影响 `git fetch` / `git push`。是否修改由作者决定。
2. AC6 许可问题，见上表。
3. `core.autocrlf=true`：Windows 检出时 LF 会被转成 CRLF。仓库已加 `.gitattributes`，强制 `*.sh`、`*.py`、`Makefile`、`*.ld` 保持 LF，否则 bash 脚本会因多出的 `\r` 无法运行。
