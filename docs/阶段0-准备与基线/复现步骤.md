# 阶段 0：复现步骤

> 目标：从一个只有 `AGENTS.md` 和 `TODO.md` 的空目录，得到和当前进度一致的仓库状态。
> 命令均在 Git Bash 中执行。`<课程目录>` 指 `SandOS-Course` 所在路径。

## 步骤 1：检查前置工具

```bash
git --version
arm-none-eabi-gcc --version | head -1
arm-none-eabi-gdb --version | head -1
qemu-system-arm --version | head -1
mingw32-make --version | head -1      # Linux/macOS 用 make
python --version
```

**预期**：每条都打印版本号。阶段 0 本身不需要 QEMU，但阶段 1 需要，所以一并检查。
**失败时**：某条提示 `command not found`，说明该工具没有安装或不在 PATH 中，先安装再继续。

## 步骤 2：引入上游源码并固定基线

目录不是空的（已有 `AGENTS.md`、`TODO.md`），所以不能直接 `git clone`，改为初始化后抓取：

```bash
cd <课程目录>
git init -b main
git remote add upstream https://github.com/SandOcean-ovo/SandOS.git
git fetch upstream
```

**如果 `git fetch` 报 `Failed to connect to 127.0.0.1 port 7897`**：这是全局代理失效，临时绕过：

```bash
git -c http.proxy= -c https.proxy= fetch upstream
```

然后把 `main` 对齐到上游基线并打标签：

```bash
git checkout -B main upstream/main
git tag upstream-baseline-25a06bd
git rev-parse HEAD
```

**预期**：最后一条输出 `25a06bdea89a467ec7e85fe7f766705b58837961`。`AGENTS.md`、`TODO.md` 显示为未跟踪文件，不会被覆盖。
**如果提交号不同**：说明上游已有新提交，`TODO.md` 的问题索引行号可能偏移，需要重新核对，不要直接沿用。

## 步骤 3：建立 `dev` 分支和目录骨架

```bash
git checkout -b dev
mkdir -p ports/qemu-mps2 ports/stm32f103-keil tests docs .github/workflows
touch ports/stm32f103-keil/.gitkeep .github/workflows/.gitkeep
```

**预期**：`git branch` 显示 `* dev`。空目录用 `.gitkeep` 占位，内容随后续阶段落地。

## 步骤 4：静态复核历史问题

不运行任何程序，只阅读源码，确认基线里问题仍然存在：

```bash
grep -n "OS_SemInit" -A6 rtos/Src/os_core.c            # 看有没有给 count 赋值
grep -n "void OS_ExitCritical" -A8 rtos/Src/os_core.c  # 看退出时是否无条件开中断
grep -n "72000000" rtos/Portable/ARM_CM3/os_cpu.c      # 固定 72 MHz（基线应能搜到）
```

**预期**：
- `OS_SemInit` 里只有 `List_Init`，没有 `count = ...`；
- `OS_ExitCritical` 在嵌套归零后调用 `OS_Enable_IRQ()`；
- 第三条能搜到 `72000000`（阶段 1 之后搜不到，因为已改为 `OS_CPU_CLOCK_HZ`）。

这一步的结论只是“静态阅读所见”，写在《基线与环境记录》第 2 节，**不能写成已复现**。

## 步骤 5：编写文档并提交

把本目录三份文档放入 `docs/阶段0-准备与基线/`，勾选 `TODO.md` 中已满足验收的阶段 0 项，然后：

```bash
git add -A
git commit -m "docs: 阶段0基线记录、M1 API契约草案与目录骨架"
```

**预期**：`git log --oneline` 中，上游的 `25a06bd` 之上有这个提交。
