# 文档索引与写作规则

## 目录结构

文档按阶段分子目录，目录名与文件名均使用中文。每个阶段目录包含：

| 文档 | 内容 |
|---|---|
| 工作记录 | 本阶段做了什么、为什么这样做、与 `TODO.md` 逐项对照的完成度、已知限制、下一步 |
| 复现步骤 | 有序的命令步骤，每步写明预期结果和失败时的去向，末尾给出完成判据 |
| 代码说明 | 新增或修改的每个文件做了什么、设计理由、关键细节 |
| 排错记录 | 实际遇到的问题：现象、定位过程、原因、修复、教训 |
| 验证记录 | 实际运行的证据：源码版本、工具版本、命令、预期、实际 |

阶段 0 的文档按实际情况有所不同（见下表），其余阶段尽量齐全。

## 写作规则

1. **文件名和正文用中文**，代码标识符、命令、路径保持原样。
2. **只写实际做过、实际运行过的事**。没有运行的写“未验证”并说明原因；静态阅读不等于复现。
3. **每个动作都能被复现**：写清命令、工作目录、预期输出和失败时的处理。
4. **证据对应结论**：说明验证证明了什么，没有证明什么。
5. **新增代码要写详细注释**：C 函数用 Doxygen 格式（`@brief`、`@param`、`@return`、`@note`），文件头说明用途；汇编、链接脚本、脚本同样注释清楚原因。并在该阶段《代码说明》里写明新增代码做了什么。
6. 修改上游文件时，在《工作记录》“修改了上游文件”一节列出，并确认其余内核文件与上游基线无差异。
