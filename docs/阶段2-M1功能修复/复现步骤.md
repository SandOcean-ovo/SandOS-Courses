所有命令在仓库根目录的 Git Bash 执行。本机需要 Arm GCC、QEMU、GDB、Python 和 mingw32-make；Linux 用 make，并按需设置 `PYTHON=python3 GDB=gdb-multiarch`。

## 1. 构建并验证计数边界

```bash
mingw32-make -C ports/qemu-mps2 APP=../../tests/target/sem_count.c
python tests/scripts/run_qemu.py ports/qemu-mps2/build/sem_count.elf --case SEM-01
```

预期 28 行 CHECK 全部 PASS，`isr_call_runs_in_svcall` 通过，最后 `TEST:PASS`、`RESULT: PASS qemu exit=0`。失败时先查看具体 CHECK 名称，再看《排错记录》；不要只检查编译成功。

该程序不启动调度器，正计数消费在 Thread 模式进行；ISR 边界通过真实 SVC 进入。它不证明阻塞或 ISR 竞争正确，阻塞另由下一步测试。

## 4. 重现 GDB pending 干扰（诊断实验）

以下仅在忽略的 build 目录生成临时检查脚本，不修改完成版内核。运行器中使用的 main.elf 可先通过 `mingw32-make -C ports/qemu-mps2` 构建。

```bash
python - <<'PY'
from pathlib import Path
context = Path('tests/gdb/context_switch.gdb').read_text(encoding='utf-8')
probe = context.replace('# PREPARE_OLD_RETURN',
    'set *(unsigned int *)0xe000ed04 = 0x04000000\n# PREPARE_OLD_RETURN', 1)
entry = Path('tests/gdb/pendsv_frame.gdb').read_text(encoding='utf-8').replace(
    'source tests/gdb/context_switch.gdb', 'source tests/build/pending_tick_context.gdb')
Path('tests/build/pending_tick_probe.gdb').write_text(entry,encoding='utf-8')
# 先删除清 pending 的动作，刻意重现旧观察窗口：这是故障诊断版。
Path('tests/build/pending_tick_context.gdb').write_text(
    probe.replace('set *(unsigned int *)0xe000ed04 = 0x02000000\n',''), encoding='utf-8')
Path('tests/build/pending_tick_fixed.gdb').write_text(probe,encoding='utf-8')
PY
python tests/scripts/run_gdb.py ports/qemu-mps2/build/main.elf tests/build/pending_tick_probe.gdb --timeout 15
```

预期运行器退出 1，`old_task_exception_return FAIL`，after_return 的 xPSR 异常号低位为 15（SysTick）。再执行 `cp tests/build/pending_tick_fixed.gdb tests/build/pending_tick_context.gdb`，重复上述 run_gdb.py 命令，预期 37 检查全部通过、退出码 0。不要将故意失败的临时脚本当作稳定版本交付。
