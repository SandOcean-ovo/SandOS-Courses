## V2-001：先复现，再修复计数

修复前以旧单参数 API 编译 SEM-01；该版测试检查错误状态非 OS_OK（当时还没有新错误码），不以编译失败冒充缺陷复现。28 检查中 12 失败，TEST:FAIL，运行器退出 1。代表输出：

```text
CHECK init_zero_overwrites_poison FAIL
CHECK init_three_overwrites_poison FAIL
CHECK task_post_overflow_error FAIL
CHECK task_overflow_does_not_wrap FAIL
CHECK isr_post_overflow_error FAIL
CHECK isr_overflow_preserves_output FAIL
```

之后保留相同检查目标，更新为双参数调用，并明确要求 OS_ERR_OVERFLOW。修复后 28 检查全部 PASS，QEMU 自然退出 0，运行器退出 0。

- 初值覆盖 0、3、UINT16_MAX；对非零预填内存初始化后检查 count 与空等待表。
- 消费初始许可至 0；正计数消费不依赖调度器。
- task/ISR 都覆盖到达上限、溢出、重复溢出；ISR 由真实 SVC 调用并核对 IPSR=11。
- 空指针和可选输出参数、失败保留输出也通过。

证据：`tests/build/logs/SEM-01-before.log`、`SEM-01-before.build.log`、`SEM-01.log`、`SEM-01.build.log`；旧测试源副本 `tests/build/sem_count-before.c` 仅适用于旧 API，是历史复现资料，不是完成版构建入口。

## V2-002：真实任务 FIFO 与许可交接

SEM-02 的 19 检查全部 PASS。A（优先级 2）先等待；B（优先级 1）借助 gate 后到。producer 两次 post 依次唤醒 A、B，事件 1～7 均在 tick=0 发生。两次直接交接不增加 count；最终被测等待表为空、就绪队列和位图一致。QEMU 自然退出 0，运行器退出 0。

证据：`tests/build/logs/SEM-02.log`。这验证了任务版的阻塞、不同优先级 FIFO 交接和无 tick 唤醒抢占；不验证 ISR 唤醒链。
