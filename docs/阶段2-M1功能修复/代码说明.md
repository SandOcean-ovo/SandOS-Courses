初始化不是把对象清零：它明确设置 count，并用 List_Init 清空等待表。调用者须保证没有并发访问、对象未发布；对使用中的对象重置仍不支持。

post 的两条分支分别表示“累积一个无人领取的许可”和“把许可直接交给一个等待者”。有等待者时不增加 count，否则被唤醒任务之后还可能再次消费同一份许可。任务版临界区保证此次边界检查与加一不会被普通中断拆开；原临界区恢复问题另有 TODO，本轮没有修复。

ISR 版仅增加上限拒绝，失败不清掉调用者的输出标记。已有成功路径仍可能把先前 TRUE 清成 FALSE，也尚无独立保存/恢复保护；本轮没有修改它们，因此仍不能将整个接口视作已完成中断安全验证。

## 确定任务顺序

SEM-02 的 B（优先级 1）先等 gate，A（优先级 2）因此先进入被测信号量等待表。producer（优先级 3）释放 gate 后，B 才成为第二个等待者。producer 两次 post 应分别唤醒 A、B；每个被唤醒任务记录事件后用正延时再次阻塞，让 producer 继续。事件 1～7 的顺序验证许可交接和抢占发生在 post 返回之前，不能只靠最后两任务都运行过来判断正确。

SysTick 被测试任务关闭，整个观察期间 tick 相同；此设计隔离时间片，不代表真实系统应关闭 tick。通用的事件记录器和退出支持继续来自阶段 1。

ISR 不能根据刚唤醒的单个任务或陈旧 NextTCB 直接决定目标：嵌套中断可能已经使更高任务就绪。因此 Yield 进入保护后根据全部 ReadyList／位图重选。每层 ISR 使用独立局部标记；FALSE 不取消其他层已挂起的 PendSV。PendSV 保持本端口最低优先级，等活动中断链完成后执行原上下文切换，未修改切换汇编或栈布局。

PRIMASK 保护覆盖队列复制，临界区长度随 MsgSize 增长；本轮验证正确性，未测真机最坏关中断时间。只有所有访问同一结构的路径使用一致保护才成立，因此 tick 也须保护，不能只把新函数包住。

| `tests/scripts/run_all.sh` | 增加 START-01、START-02 和两负例；WRAP 环境值只用于两项夹具调用，正常工程不包装。共 44 个运行项 |

不能在 C 启动函数设置 RUNNING，也不能仅在汇编写入 CurrentTCB 后立刻设置：此时新 PSP／寄存器尚未全部恢复。发布点放在 ORR LR 之后、CPSIE 之前；R2／R3 为硬件帧稍后恢复的寄存器，不破坏已恢复的 R4～R11。首任务恢复与正常任务切换经过同一恢复尾部，后者再次写 RUNNING 不引入状态变化。两份汇编写入常量 1 与头文件约定固定，若未来改值必须同步两份端口。

启动前 tick 不计入系统时间是明确契约，不是测试中删除 tick；RUNNING 发布后，即使仍在 PendSV 异常返回前，高优先级 SysTick 也可合法抢占。START-02 专门验证这一边界。当前变量名 g_OSRunning 保留兼容，但非零判定已不再等价于可调度；所有通用内核读点已核对。

## 2026-11-12 时钟与 tick 边界专项

| 文件 | 改动与原因 |
|---|---|
| `ports/qemu-mps2/os_board.h`、`clock.c` | 新板级只读 getter OS_BoardClockHz 返回模型固定 25 MHz；保留板级常数，CPU 端口不再直接依赖该宏；修正优先级说明为按实际位数选择 |

返回协议从 void 改为 uint32_t，所有端口调用者／桩必须一起重新编译，不能混用旧对象文件。使用 0／1 的简单端口状态，避免 os_cpu.h 反向依赖 os_core.h 的 OS_Status。现有内部 Start 是唯一生产调用者，已检查返回值；RISC-V 端口原本就未完成签名／启动适配，不在本轮声称支持。

不能先除以 1000：1500 Hz×2 ms 应为 3 个周期，旧计算得到 2；1001 Hz×1000 ms 应为 1001，旧计算得到 1000。先转换成 uint64_t 再相乘可容纳两个 uint32_t 的最大乘积，然后校验整除与范围后才转回 uint32_t。计数 0x1000000 对应最大合法 LOAD=0xFFFFFF；1 个周期对应 LOAD=0，ARM 明确说明其不能产生所需的周期请求，因此另行拒绝。

板级 getter 是“已经建立的 CPU 时钟”而不是晶振值；本轮只实现 QEMU 固定频率。STM32 的实际时钟初始化／更新属于板级职责，不在通用端口硬编码 8 MHz 或 72 MHz。动态改频、暂停后时间补偿和任意精度 tick 不在此入口支持范围。
