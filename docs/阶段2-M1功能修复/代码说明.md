初始化不是把对象清零：它明确设置 count，并用 List_Init 清空等待表。调用者须保证没有并发访问、对象未发布；对使用中的对象重置仍不支持。

post 的两条分支分别表示“累积一个无人领取的许可”和“把许可直接交给一个等待者”。有等待者时不增加 count，否则被唤醒任务之后还可能再次消费同一份许可。任务版临界区保证此次边界检查与加一不会被普通中断拆开；原临界区恢复问题另有 TODO，本轮没有修复。

ISR 版仅增加上限拒绝，失败不清掉调用者的输出标记。已有成功路径仍可能把先前 TRUE 清成 FALSE，也尚无独立保存/恢复保护；本轮没有修改它们，因此仍不能将整个接口视作已完成中断安全验证。

## 确定任务顺序

SEM-02 的 B（优先级 1）先等 gate，A（优先级 2）因此先进入被测信号量等待表。producer（优先级 3）释放 gate 后，B 才成为第二个等待者。producer 两次 post 应分别唤醒 A、B；每个被唤醒任务记录事件后用正延时再次阻塞，让 producer 继续。事件 1～7 的顺序验证许可交接和抢占发生在 post 返回之前，不能只靠最后两任务都运行过来判断正确。

SysTick 被测试任务关闭，整个观察期间 tick 相同；此设计隔离时间片，不代表真实系统应关闭 tick。通用的事件记录器和退出支持继续来自阶段 1。
